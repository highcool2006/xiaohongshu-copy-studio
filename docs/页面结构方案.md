> 版本：v1.0
> 日期：2026-09-26
> 范围：Phase 2 第一部分「页面结构」的全部已确认结论
> 配套文档：`docs/产品需求文档.md`（产品要什么）、`docs/技术架构决策.md`（技术怎么做）

> ⚠️ **V2 说明（2026-09-26）**：本文档记录的是 **Day 1 MVP 的单页结构**（左输入 + 右结果）。
> **V2 的页面结构升级为桌面端工作台**（顶部导航：工作台 / 风格库 / 数据看板 / 资产库；左侧内容生产配置区；右侧批量结果区），

> 本文档保留作为 MVP 页面结构的历史记录。

## 本文档的职责

回答「**界面长什么样**」：有哪几个页面、分成哪些区域、每个区域放什么、信息层级如何、用户视线怎么走。

**不包含**：产品需求（见 PRD）、技术实现与状态设计（见技术架构决策）。

---

## 1. 页面清单：单页

**整个 MVP 只有一个主界面，不使用路由。**

**理由：**

1. 当前是单线工作流：输入 → 生成 → 查看 → 编辑/重写 → 复制
2. 没有历史记录、详情页、多层级导航的需求
3. 与既定技术决策一致（D4 不流式、D5 单棵状态树、D6 单一工程、D8 失败保留输入）
4. 不为 MVP 引入路由与跨页面状态管理

**接受的代价（已确认）：** 页面内需要靠**结构和交互**让用户明确感知"结果已生成"——由"结果区信息条"承担（见第 4 节）。

---

## 2. 布局：左右分栏

```
┌──────────────────────────────────────────────┐
│  顶部：产品名 · 一句话定位                      │
├────────────────┬─────────────────────────────┤
│                │                             │
│  输入区         │   结果区                    │
│  · 产品 / 主题   │   ┌─────────────────────┐  │
│  · 卖点标签      │   │ 信息条 / 状态区       │  │
│  · 风格多选      │   ├─────────────────────┤  │
│  · 篇数          │   │ 卡片列表（单列滚动）   │  │
│  · 生成按钮      │   │                     │  │
│                │   └─────────────────────┘  │
│  （左栏固定不动） │   （结果区独立滚动）        │
└────────────────┴─────────────────────────────┘
```

| 项 | 决定 |
|---|---|
| 结构 | 左输入区 + 右结果区 |
| 滚动 | **结果区独立滚动**；左栏天然保持可见，**不额外做 sticky** |
| 目标视口 | **1440px 桌面视口**为当前主要验收场景 |
| 窄屏 | **暂不做响应式断点**，留到视觉打磨阶段 |

**窄屏原则（约束）**：未来窄屏下从「左右分栏」切换为「上下堆叠」，**当前设计不得堵死这条路径**。

**为什么选左右分栏：**

1. 结果出现在同一视野内，"感知结果已生成"的风险由布局本身化解
2. 与 D4 配合：等待态在右栏显示，左栏表单完全保持可用
3. 与 D8 配合：错误显示在右栏，输入区全程不被碰过
4. 与任务书优秀线样例的「左栏表单 + 结果区」结构参照一致
5. 1440px 下横向空间充足

## 3. 顶部区域

**极简纯文字：产品名 + 一句话定位。**

| 做 | 不做 |
|---|---|
| 产品名（纯文字） | 图形 Logo |
| 一句话定位（小字、低对比度，不与产品名争夺注意力） | 设置 / 关于 / 历史入口 |
| | 任何附加功能入口 |

**一句话定位的具体文案内容后续再定**，此处只确定结构。

**不做页脚。** 任务书 2.1 描述第一档（不合格线）时明确点名「页脚仍挂着『超级AI大模型』式口号」——页脚在这种单页工具里没有信息价值，是最容易踩到一档特征的位置。

---

## 4. 结果区

**两层结构：顶部信息条 + 下方卡片列表。**

### 4.1 信息条

**MVP 阶段只展示确定性信息：**

- 本次生成篇数
- 本次使用的风格 / 风格数量

**暂不加入评分统计**（`average_score` 程序计算但不在界面展示）。

**信息条同时承担"结果已生成"的信号作用**——这是"单页"这一选择所接受的代价的落点：结果区顶部出现明确的信息条，是一个天然、不依赖动效的"结果已到"信号。

### 4.2 四种状态

四种状态**统一在结果区内部切换**：

| 状态 | 结果区显示 | 输入区 |
|---|---|---|
| **空**（还没生成） | 一句引导文案，告诉用户"填好左侧后点生成" | 正常可用 |
| **生成中** | 信息条位置显示"正在生成…" + 卡片区显示加载占位 | **保持完整可用** |
| **失败** | 错误条（错误文案 + "以下是上一次的结果" + 重试按钮） | **完全不动** |
| **有结果** | 信息条（篇数 / 风格）+ 卡片列表 | 保持可用 |

**生成失败时**：输入区保持不变、结果区显示错误与重试、**不清空用户已填内容**；若此前已有结果，旧结果完全保留并仍可操作。错误 UI 的具体规则见技术架构决策文档第 13 节。

## 5. 卡片

### 5.1 排列：单列

| 决定 | 内容 |
|---|---|
| 排列 | **单列**，纵向滚动展示 5～10 篇 |
| 正文 | 超过约 4 行时**截断 + 提供「展开」** |

**理由：**

1. 正文是核心交付物，需要足够阅读宽度
2. 便于后续就地编辑（窄栏里编辑体验差）
3. 避免双列带来的卡片高度不一致与复杂布局
4. "生成了几篇"已由信息条告知，不需要靠网格总览

### 5.2 卡片内部结构

**顺序（自上而下）：**

```
风格标签 + 内容方向标签
        ↓
       标题            ← 最醒目
        ↓
       正文            ← 主要阅读内容（超长截断 + 展开）
        ↓
     话题标签
        ↓
  操作区：复制 / 编辑 / 换风格重写   ← 常显，不依赖 hover
        ↓
      评分区域
```

| 项 | 决定 |
|---|---|
| 标题 | 最醒目的内容 |
| 正文 | 主要阅读内容；较长时截断并提供「展开」 |
| 风格标签 | 显示 |
| 内容方向标签 | 显示（取自 8 个已确定的内容方向） |
| 话题标签 | 显示（数据层不带 `#`，由程序渲染 `#`） |
| 操作按钮 | **始终可见，不依赖 hover**（功能藏起来是缺陷，不是细节） |
| 评分区域 | 显示爆款潜力自评分 |

**不展示 persona 标签**：本系统不设「人设」概念。

## 6. 卡片交互

### 6.1 就地编辑

**就地展开编辑，不使用浮层 / 模态框 / 侧边抽屉。**

- 「完成 / 取消」明确结束，**不做自动保存**
- 编辑态保持合理的最小高度，减少页面跳动
- 普通编辑**只改前端本地状态，不调用 AI**
- 编辑态下操作区只显示「完成 / 取消」，隐藏「复制」与「换风格重写」

### 6.2 换风格重写

```
点击「换风格重写」
 → 当前卡片进入重写态
 → 展示可选目标风格
 → 用户选择目标风格
 → 点击「确认重写」
 → 才正式调用 AI
（同时提供「取消」）
```

**选择风格后不得立即调用 AI，必须经过确认**——该操作有真实成本（AI 调用 + 等待），不应一步触发。同时避免误触。

**重写成功后新文案直接替换当前卡片**；MVP 不做版本历史 / 对比 / 撤销。点「取消」则保留原文案。

### 6.3 重新评分

用户编辑文案后评分标记为可能过时，可点击「重新评分」；未修改时也允许主动点击。评分失败时原有评分不清空。

## 7. 页面信息层级总排序

| 层级 | 元素 | 说明 |
|---|---|---|
| **一级**（核心行动 / 核心产出） | 生成按钮、文案标题 | 生成按钮是全页唯一行动焦点，视觉权重最高 |
| **二级**（核心输入 / 核心内容） | 产品 / 主题、卖点、文案正文 | |
| **三级**（生成控制 / 结果概览） | 风格、篇数、结果信息条 | |
| **操作层**（功能操作） | 复制、编辑、换风格重写 | **不归入第四级**——虽非视觉主角，但是用户完成任务的重要功能 |
| **四级**（辅助信息） | 风格标签、内容方向标签、话题标签、评分区域 | |
| **页面身份层** | 产品名、一句话定位 | 保持低视觉权重，不参与表单与结果内容的竞争 |

**一处刻意的判断**：产品名与定位的视觉权重最低。这是一个**工具**，不是内容网站——用户来是为了做事，品牌感靠统一的设计语言体现，不靠放大 Logo。

---

## 8. 页面视线路径

**空态：**

```
顶部身份
 → 左栏产品 / 卖点
 → 风格 / 篇数
 → 生成
 → 右栏空态引导
```

**有结果：**

```
左栏输入与生成控制保持可见
   ↕
右栏结果信息条
 → 文案标题
 → 正文
 → 标签 / 评分
 → 操作
```

用户完成一轮生成后，可以继续修改左侧输入并再次生成。

---

## 9. 明确不做

- 多页面、路由、历史记录页、详情页、多层级导航
- 居中起步+生成后变形的布局形态
- 浮层 / 模态框 / 侧边抽屉（编辑与重写均就地展开）
- 双列网格
- 页脚
- 顶部区域的 Logo、设置、关于、历史入口
- 卡片操作按钮的 hover 显示
- 全局 Toast、顶部错误横幅
- 评分统计进入信息条
- 窄屏断点（留到视觉打磨阶段）
- 人设输入字段与 persona 标签
- 「复制全部」
