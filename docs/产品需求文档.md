## 1. 产品概述

### 1.1 产品名称

**小红书爆款文案工坊** 【任务书】

### 1.2 一句话定位

> 输入产品和卖点，批量生成不同人设、不同风格的平台种草笔记（标题 + 正文 + 话题标签），并可继续编辑、换风格重写。 【任务书】

**范围说明**：1.1 原句后半段还有“最终沉淀为可复用的个人风格模板库”，但“风格模板库”属任务书 1.4 进阶功能，**不属于 MVP**。因此本期定位只落实到“生成 + 编辑 + 换风格”。 【任务书】

### 1.3 能力主线与难度定位

| 项 | 内容 | 来源 |
|---|---|---|
| 能力主线 | AI 内容生成 × 审美表达 × 风格资产沉淀 | 【任务书】 |
| 技术难度 | ★★☆☆☆（核心链路为纯文本生成，无复杂后端） | 【任务书】 |
| Demo 效果 | ★★★★★（生成结果本身即可作为作品展示） | 【任务书】 |
| 建议形式 | 个人独立完成，周期 7 天 | 【任务书】 |

### 1.4 核心用户

| 用户 | 依据 |
|---|---|
| **小商家** | 【任务书】 |
| **个体创作者** | 【任务书】 |

**共同特征**：不擅长写作，但需要批量获得可发布的笔记。【任务书】

**画像边界**：任务书仅给出以上两类用户。年龄、性别、平台使用经验、预算等画像细节，任务书未提及，**本文档不做假设**。 【待确定】

### 1.5 用户痛点

| 层次 | 痛点 | 来源 |
|---|---|---|
| 能力痛点 | 不熟悉平台内容风格，写不出有「网感」的种草笔记 | 【任务书】 |
| 效率痛点 | 一篇篇手写速度慢、质量不稳定 | 【任务书】 |
| 资产痛点 | “会写爆款”的经验没有被沉淀成可复用的系统 | 【任务书】 |

### 1.6 核心价值

> 把「会写爆款」的经验沉淀成一套可复用的生成系统，让不擅长写作的人也能批量获得可发布的笔记。 【任务书】

三个价值关键词（均出自任务书）：**批量** · **可发布** · **有网感**。

## 2. 核心用户流程

```
① 输入产品与卖点            【任务书 1.3】
        ↓
② 选择风格（4～6 种人设）    【任务书 1.3】
        ↓
③ 一键生成 5～10 篇          【任务书 1.3】
   每篇 = 标题 + 正文 + 话题标签
        ↓
④ 查看「爆款潜力」自评分     【任务书 1.3】
   → 决定优先发布哪一篇
        ↓
⑤ 复制 / 编辑 / 换风格重写   【任务书 1.3】
        ↓
⑥ 发布到平台                【产品设计】
   在工具之外发生，不属于本产品功能
```

**流程说明**：第 ⑥ 步为讲通完整流程而补充，任务书**未**把它列为功能，**不作为需求**。 【产品设计】

## 3. 功能范围

### 3.1 MVP（必须完成）

任务书 1.3 明确：以下四项构成一周 MVP 验收范围，**全部完成即视为达成**。

| # | 功能 | 具体范围 | 来源 |
|---|---|---|---|
| 1 | **批量生成** | 输入主题与卖点，一键生成 5～10 篇不同风格的笔记：标题 + 正文 + 话题标签 | 【任务书】 |
| 2 | **风格选择** | 提供基础风格选择，如亲切分享、专业测评、搞笑段子、干货攻略等 4～6 种 | 【任务书】 |
| 3 | **结果操作** | 每篇笔记可复制、可编辑、可换风格重写 | 【任务书】 |
| 4 | **爆款潜力自评分** | 给出自评分，帮助用户判断优先发布哪一篇 | 【任务书】 |

**设计意图**：第 4 项的存在理由是“帮助用户判断优先发布哪一篇”——一个不改变用户行为的评分等于没做。 【产品设计】

### 3.2 加分项（有时间再做）

任务书 1.4 明确定位为“供学有余力者选做，也是评分的主要区分点”。

| # | 加分项 | 来源 | 风险提示（我们的判断） |
|---|---|---|---|
| 1 | 自动生成封面图或封面建议（与图像生成 API 结合） | 【任务书】 | 引入外部 API，成本与不确定性最高 【产品设计】 |
| 2 | 可维护的私有风格模板库 | 【任务书】 | 需要先有验证过的爆款规律可沉淀 【产品设计】 |
| 3 | 多平台一键适配（公众号图文、短视频口播稿） | 【任务书】 | — |
| 4 | A/B 标题对比测试与数据回收 | 【任务书】 | 需要时间积累真实数据，一周内易做成空壳 【产品设计】 |
| 5 | 历史生成记录与效果追踪看板 | 【任务书】 | 同上，依赖历史数据 【产品设计】 |

> 风险提示列属我们的判断，**不改变**任务书对这五项“选做加分”的定位。

### 3.3 暂不做（本阶段明确排除）

以下内容任务书**未提及**，为控制范围，本阶段明确排除：

| 项 | 说明 | 来源 |
|---|---|---|
| 账号 / 登录 / 用户系统 | 任务书未提及，本期排除 | 【产品设计】 |
| 多端同步 | 同上 | 【产品设计】 |
| 团队协作 | 同上 | 【产品设计】 |
| 站内直接发布到平台 | 发布在工具之外发生，见第 2 节 | 【产品设计】 |

### 3.4 范围边界说明

- **不做自行扩张**：MVP 四项之外不新增核心功能。
- **不做自行缩减**：MVP 四项“全部完成即视为达成”，少做一项不算达成。
- 加分项属“选做”，完成与否不影响 MVP 达成判定。 【任务书】

## 4. 视觉设计方向与产品气质

任务书提供了三档效果对照样例。本章内容全部取自任务书对样例的描述。

### 4.1 底线：必须避开的特征（第一档「一眼 AI」= 一票否决）

- 视觉：AI 紫渐变打底，红、绿、粉、黄多种高饱和渐变卡片撞色，**五张结果卡五种配色**，没有统一规范
- 文案：emoji 密度过高，感叹号与浮夸数字堆砌（如“转化率提升 300%”“好评率 99.9%”），专业感为零
- 结构：功能卖点、生成表单、结果列表之间没有层级与呼吸感，页脚仍挂着“超级AI大模型”式口号
- 判定：**一票否决项，无需再考察功能完成度**

【任务书】

### 4.2 目标气质（第三档「精致成品」）

| 面向 | 要求 | 来源 |
|---|---|---|
| 视觉 | 明确的设计语言：暖白纸感底色配小红书红点缀；统一的卡片与间距节奏；红色仅作点缀，克制而有记忆点 | 【任务书】 |
| 视觉体系 | 色彩、间距、圆角**成体系** | 【任务书】 |
| 文案 | 微文案贴合使用场景，克制而有网感。示例：`预计消耗 8 点额度 · 约 40 秒完成`、`上次同配置平均指数 85` | 【任务书】 |
| 文案禁忌 | 实现细节不得暴露给用户（反面示例：界面上显示 `消耗 tokens 8,742`） | 【任务书】 |
| 结构 | 表单、结果、统计构成完整工作流；**结果卡之间要有差异化**（反面：五张卡样式完全一致、密度偏高） | 【任务书】 |
| 控件 | 使用卖点标签、分段控件等精致控件（反面：全套系统默认控件） | 【任务书】 |
| 细节 | 每篇笔记带封面建议、爆款指数进度条、A/B 测试入口等体现产品深度的细节 | 【任务书】 |

> **关于本表“细节”一行的边界说明**：该行内容取自任务书对第三档「精致成品」的描述，属**效果样例说明**，**不判定为 MVP 必做功能**。任务书内部存在“三档功能一致”与此处出现进阶功能之间的表述张力，该冲突已在第 7 节「待确定事项」保留，**是否实现待后续决定**。 【待确定】

### 4.3 分档判断标准

- 三档样例**功能与演示数据完全一致**（同一款演示产品「山野冷萃 · 冻干咖啡粉」），**差异仅在视觉设计与完成度**。 【任务书】
- 进入第三档的关键**不是功能更多，而是每一处细节都有被想过**。 【任务书】

## 5. 典型使用场景

> 本场景由我们构造，但每个要素均有任务书锚点。 【产品设计】

**演示产品**：山野冷萃 · 冻干咖啡粉 【任务书】（第二章指定的统一演示产品）

一位卖冻干咖啡的**小商家**，想把产品推给小红书上爱露营的年轻人。他不擅长写文案，也知道自己写出来的东西“没有网感”。

他的操作路径：

1. 打开工具，输入**产品与卖点** 【任务书】
2. 从 **4～6 种风格**里挑几种 【任务书】
3. **一键生成 5～10 篇**不同风格的笔记 【任务书】
4. 看**爆款潜力自评分**，决定先发哪一篇 【任务书】
5. 对选中的那篇**编辑，或直接换风格重写** 【任务书】
6. 复制出去发布（在工具之外） 【产品设计】

### 6.1 任务书给出的硬标准

| 项 | 内容 |
|---|---|
| MVP 达成 | 1.3 四项全部完成即视为达成 |
| 交付物 | 三项**缺一即视为未完成**：① 可访问的作品链接（或可在本地一键运行的源码包）+ 源码仓库地址；② 90 秒现场 Demo，按「问题 → 演示 → 边界」结构讲解，超时即截断；③ AI 使用过程记录（AI 对话导出 或 每日 commit 历史） |
| 评审维度 | 视觉设计 · 文案内容 · 产品完成度 · AI 使用痕迹 |
| 否决线 | 触达第一档特征即一票否决，无需再考察功能完成度 |
| 优秀线 | 判断依据是“每一处细节都有被想过”，而非功能更多 |

【任务书】
