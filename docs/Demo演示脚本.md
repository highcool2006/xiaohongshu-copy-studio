# 90 秒现场 Demo 脚本

> 依据任务书 6.1：交付物之一，按「**问题 → 演示 → 边界**」结构讲解，**超时即截断**。
> 计时以「说出口」为准，不要等界面动画。

## 预备（演示前 5 分钟做完）

| # | 检查 | 命令 / 动作 |
|---|---|---|
| 1 | 后端已起 | `npm run dev`（或 `npm start`） |
| 2 | 页面可访问 | 打开 `http://localhost:5173`，确认可用 |
| 3 | **预跑一次生成** | 用下方演示输入完整跑一遍，确认凭据有效、响应正常 |
| 4 | 清空状态 | 刷新页面（结果与资产清空，回到首屏） |
| 5 | 视口 | **1440px 桌面视口**（任务书截图基准） |
| 6 | 关掉无关窗口 | 通知、终端日志等 |

**演示产品**（与任务书样例一致，便于对照）：`山野冷萃 · 冻干咖啡粉`

```
产品 / 主题：山野冷萃冻干咖啡粉
核心卖点：3秒速溶 / 0糖0添加 / 单杯成本低
补充真实细节：周三下午在工位犯困，翻出这根。第一口比想象中苦，我愣了一下。
目标用户：上班族
使用场景：办公室
文案类型：强种草推荐
文案风格：亲切分享
```

---

## 第 1 段 · 问题（0:00 – 0:20）

**说**（不要念稿，看着屏幕讲）：

> 小商家和个体创作者最缺的不是产品，是**写得出有网感的笔记**。
> 一篇篇手写慢，质量还不稳定。
> 这个工具做的事是：**输入产品和卖点，批量产出可以直接发布的种草笔记**。

**动作**：不操作，让左栏完整停在屏幕上，观众自己能看到九个分区。

---

## 第 2 段 · 演示（0:20 – 1:10）

### 2.1 填输入（0:20 – 0:35）

> 左边是输入。产品、卖点必填；目标用户和场景可以选，也可以让 AI 推测。

**动作**
1. 填「产品 / 主题」（可直接选已存好的输入，若浏览器自动填充则更快）
2. 填「核心卖点」：三个卖点一次粘贴，按回车自动拆成标签 —— **这里停留 1 秒让观众看清拆标签**
3. 点「目标用户 → 上班族」「使用场景 → 办公室」

### 2.2 说明两个关键控制项（0:35 – 0:45）

> 这里是**文案类型**——决定这篇是什么体裁，是强种草、测评、还是避坑对比。
> 下面是**文案风格**——决定用什么语气说。
> 两个是分开的：同样的内容，可以写成测评，也可以写成段子。

**动作**：点选「强种草推荐」，再点「亲切分享」。

> 这一段是**加分点**：讲清「体裁」与「语气」分层，是产品想过的证据。

### 2.3 生成（0:45 – 0:55）

**动作**：点「生成文案」。等待时**不要沉默**：

> 一次请求完成策略、角度、正文、自检和评分，不是一篇篇调。

生成完成后（约 30-60 秒，若超时见兜底）：

> 六篇，风格和角度都是错开的。

### 2.4 展开分析 + 换风格（0:55 – 1:10）

**动作**
1. 指一下卡片的**摘要行**：`83/100 · AI 味低 · 合规低`
2. 点「展开分析 ▾」—— 抽屉展开，露出创作角度 / 封面建议 / 六维评分
3. 指出**创作角度**那一行（本篇讲的是哪一件事）
4. 收起抽屉，点一篇的「换风格重写」，选另一个风格

> 每篇都能改、能换风格重写、能重新评分。**复制出来的格式是标题、正文、话题标签，可以直接粘到小红书。**

---

## 第 3 段 · 边界（1:10 – 1:30）

> 最后说边界，这个更重要。

**说**：

> **第一，不编造事实。**
> AI 只允许使用你填的产品信息和你的真实经历。你没提过的口感、成分、价格、销量，它一个字都不会写。
> 想让它写得更具体，你得在「补充真实细节」里填自己的真实经历——那是唯一的来源。

> **第二，不伪造平台数据。**
> 这个工具**没有连接小红书**，也拿不到曝光、点赞、收藏。数据看板里显示的全是你自己的操作记录，没有发生过就是 0。
> 评分是**内容质量自评**，不是爆款预测，我们不承诺任何流量结果。

> **第三，不替你做发布。** 发布在工具之外发生。

**收尾一句**：

> 它不替你想卖什么，只把你已经想清楚的东西，写成能发出去的样子。

## 兜底方案

| 情况 | 处理 |
|---|---|
| **生成超时 / 失败** | 不说"网络问题"，说：「这里我已经预跑过，我们直接看结果」——切到已打开的结果页签。**不要现场重试第二次**，会吃掉时间 |
| **凭据失效（AI_CALL_FAILED）** | 切 Mock 模式：`VITE_USE_MOCK_DATA=true npm run dev:web`。**说明这是离线演示数据**，不要假装是真调用 |
| **页面白屏** | 提前开好一个已生成结果的页签作为备用 |
| **被问「爆款率多少」** | 明确回答：不预测、不承诺。给的是内容质量自评与风险提示 |
| **被问「和 ChatGPT 写有什么区别」** | 三点：① 风格/体裁/角度是**程序约束**的，不是随机发挥；② 事实边界由校验层强制，不编造；③ 输出是结构化契约，能逐篇编辑、重写、评分、存资产 |

## 时间分配速查

| 段 | 时长 | 要点 |
|---|---|---|
| 问题 | 20s | 痛点 + 一句话定位 |
| 演示 | 50s | 填 → 选类型/风格 → 生成 → 展开分析 → 换风格 |
| 边界 | 20s | 不编造 / 不伪造数据 / 不发布 |

**超时最先砍**：2.4 的「换风格重写」。
**绝不能砍**：第 3 段边界 —— 任务书评审维度里"产品完成度"与"否定线"都指向它。
