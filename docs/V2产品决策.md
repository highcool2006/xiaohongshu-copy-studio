# 小红书 AI 内容工作台 · V2 产品决策

> 版本：v1.0
> 日期：2026-09-26
> 关系：本文档记录 V2 的产品定位与最终决策。`docs/产品需求文档.md`（Day 1 PRD）保持原样作为历史需求，不被覆盖。

---

## 1. V2 产品定位

**产品名**：小红书 AI 内容工作台

**定位**：不是"帮我写几篇 AI 文案"，而是"从产品信息出发，完成内容策略规划、批量创作、质量检查、修改、A/B 标题测试与内容复盘"。

**核心工作流**：

```
产品信息 → 内容策略分析 → 内容角度规划 → 批量创作 → 事实与合规检查
→ 原生感 / 模板感检查 → 质量评分 → 人工编辑 → A/B 标题测试
→ 复制 / 导出 → 内容复盘
```

**与 Day 1 MVP 的关系**：MVP 的四项功能（生成 / 风格选择 / 编辑·复制·重写 / 自评分）全部保留，V2 在此之上**增加策略层与工作台能力**，不删除任何既有功能。

---

## 2. 产品功能

| 区域 | 能力 |
|---|---|
| 工作台 | 产品信息（名称 / 类别 / 卖点 / 补充信息）、目标用户、使用场景、内容目标、内容方向、风格、篇数、参考文案 |
| 内容策略 | 一次生成返回「总策略 + 目标人群 + 场景 + N 个创作角度 + 多样性报告」 |
| 结果区 | 批量统计、风格统计、多样性状态、排序与筛选、批量操作 |
| 卡片操作 | 编辑 · 复制 · 重写（换风格）· 标题变体 · 发布前检查 · 收藏 |
| 风格库 | 6 个预设风格 + 用户自定义风格（localStorage） |
| 资产库 | 生成批次与文案的本地保存、查看、删除、导出 |
| 数据看板 | **本地生产数据**（真实统计）+ 用户**手动录入**的发布后数据 |

**明确不做（后续版本）**：登录、团队协作、支付、数据库、实时爬虫、自动发布、多 Agent、图片/视频生成 API。

## 3. API 契约

### 保留

| 端点 | 说明 |
|---|---|
| `GET /api/health` | 健康检查（非业务） |
| `POST /api/generate` | **V2 扩展**：请求新增可选字段；响应新增 `strategy` |
| `POST /api/rewrite` | 单篇换风格重写，返回长度 1 的 `notes` |
| `POST /api/score` | 只返回 `score`（六维，见第 5 节） |

### 追加（2026-09-27）

沿用 V2「扩展字段全部可选、保持向后兼容」的约定，**未改变任何既有字段与响应结构**：

| 端点 | 新增请求字段 | 说明 |
|---|---|---|
| `generate` | `personal_material`、`persona_note` | 用户的真实经历与身份口吻。前者是第一人称细节的**唯一合法来源**；为空时 Prompt 不得出现此类内容 |
| `generate` | `copy_type` | **文案类型（体裁）**，值域 5 种，默认「强种草推荐」。与 `goal`（意图）、`styles`（语气）分层，冲突时以它为准 |
| `rewrite` | `personal_material`、`persona_note` | 与 generate 同一份输入，避免重写时丢弃已写进文案的真实细节。**不接收 `copy_type`** |

> `generate` 的其余 V2 字段（`product_category` / `additional_info` / `target_users` /
> `scenarios` / `goal` / `reference_text` / `content_directions_preference`）已在
> `技术架构决策.md` 第 4.2 节补全。

### 新增

| 端点 | 触发方式 | 一次调用 |
|---|---|---|
| `POST /api/title-variants` | **仅用户主动点击** | 生成 3 个标题变体 |
| `POST /api/reference/analyze` | **仅用户主动提交参考文案** | 分析方法与结构，**不复制内容** |
| `POST /api/compliance/check` | **仅用户主动点击「发布前检查」** | 合规复查 |

### 调用次数原则（硬约束）

```
一次 Generate        = 1 次 AI 请求（策略 + 角度 + 正文 + 自检 + 评分 + 合规，全部在内）
一次 Rewrite         = 1 次 AI 请求
一次 Score           = 1 次 AI 请求
一次 Title Variants  = 1 次 AI 请求
一次 Reference Analyze = 1 次 AI 请求
一次 Compliance Check  = 1 次 AI 请求
```

**禁止**：每张卡单独评分 / 单独合规 / 单独检测 AI 味 —— 这些都在 Generate 内一次完成。

`strategy` **不单独**做成一个 AI 请求（避免翻倍成本与延迟）。

### `POST /api/generate` 响应（V2）

```json
{
  "information": { "status": "sufficient | limited", "message": "" },
  "strategy": {
    "summary": "...",
    "target_users": ["..."],
    "scenarios": ["..."],
    "angles": [{ "id": "angle-1", "type": "场景", "audience": "...", "scenario": "...",
                 "core_idea": "...", "hook_type": "...", "structure_type": "...", "ending_type": "..." }],
    "diversity_report": { "opening_types": 5, "structure_types": 6, "ending_types": 5,
                          "style_types": 4, "angle_types": 6, "duplicate_risk": "low" }
  },
  "notes": [ /* 见第 4 节 */ ]
}
```

## 4. 数据模型

### Note

```
{
  id,                  // 由**程序**生成，AI 不生成随机 ID
  title, body,
  hashtags[],          // 3～5 个，值不含前导 #
  style,
  content_directions[],// 内容方向标签（数组，保持既有契约）
  angle_id,            // 对应 strategy.angles 中的一篇角度
  score,               // 六维，见第 5 节
  ai_ness,             // 独立检查：AI 味（不是评分维度）
  compliance,          // 独立检查：合规
  cover_suggestion,    // { headline, visual_subject, composition } —— 只生成创意，不生成图片
  stale                // 内容被编辑后由程序置 true
}
```

**`angle` 与 `content_directions` 是两个不同概念**：

- `content_directions` = 内容方向**标签**（既有契约，数组）
- `angle` = 本篇的**具体创作角度**（每篇一个）

### ContentAngle

```
{ id, type, audience, scenario, core_idea, hook_type, structure_type, ending_type }
```

**angles 必须与 notes 一一对应**：不允许 6 篇文案只有 2 个真正不同的角度。

### 其他

- `ProductProfile`：前端输入档案（名称 / 类别 / 卖点 / 补充信息 / 目标用户 / 场景 / 内容目标 / 参考文案）
- `AiNessResult` / `ComplianceResult`：`{ risk_level: low|medium|high, issues[], suggestions[] }`
- `TitleVariant`：`{ title, type, analysis }`
- `ReferenceAnalysis`：开头方式 / 结构 / 信息密度 / 节奏 / 叙事 / 情绪强度 / 结尾 / 互动 / 可借鉴方法 / **不应复制的表达**

## 5. 评分体系（100 分制，六维）

| 维度 | 字段 | 上限 |
|---|---|---|
| 内容价值 | `content_value` | 25 |
| 具体度 | `specificity` | 20 |
| 原生感 | `native_feel` | 20 |
| 差异化 | `differentiation` | 15 |
| 结构完整度 | `structure` | 10 |
| 真实性 | `authenticity` | 10 |
| **总分** | `total` | **100** |

约束：各维度为**整数**且在区间内；`total` 必须**严格等于六项之和**；另有 `strength` / `improvement`。

**UI 名称统一为「内容质量」**，不得写作「爆款指数」「爆款概率」「预计点赞/收藏」。评分是 AI 辅助评价，**不是平台数据预测**。

**「AI 味」不是评分维度**（见第 6 节）。

---

## 6. AI 味检查（独立项）

```
ai_ness: { risk_level: "low | medium | high", issues: string[], suggestions: string[] }
```

检查重点：套模板、机械总结、过度完整、过度解释、"首先/其次/最后"、空泛价值判断、标准化结尾、相似开头、相似句式、过度使用"如果你……那么……"/"总的来说"/"值得一提"/"希望对你有帮助"、连续多篇同一结构、**仅替换产品关键词**、没有具体场景、没有具体信息、像 AI 总结而不像用户发帖。

`risk_level` 为 high 时**必须尝试自动修正并重新检查**；若仍为 high，**保留告警，不允许伪装成通过**。

---

## 7. 合规检查

```
compliance: { risk_level, issues[], suggestions[] }
```

至少覆盖：虚假事实、虚构体验、虚构用户评价、虚构销量、虚构数据、绝对化表达、夸大效果、无依据比较、虚假前后对比、恶意模仿、可能误导的表达。

**边界**：合规检查的目的是**只改风险表达**，不把正常自然的表达写得死板。

**UI 必须写明**：「AI 风险提示，不代表平台审核结果」。**不得声称"100% 过审"**。

## 8. localStorage 资产设计

```
Workspace → Product → GenerationBatch → Note → TitleVariant → Review
```

- 必须带 `schemaVersion`，以便以后迁移
- 提供：查看 / 删除 / 复制 / 导出（TXT / Markdown / JSON）
- 数据看板的「本地内容生产数据」（已生成篇数、平均质量分、改写次数、标题实验次数、复制次数等）**全部来自 localStorage 的真实操作记录**，**禁止硬编码**；无数据时显示「暂无数据」

## 9. Mock / 真实 AI 边界

| 开关 | 行为 |
|---|---|
| `VITE_USE_MOCK_DATA=true` | 走本地 Mock（**仅前端**），不产生 AI 成本；用于 UI 开发、reducer 测试、无 Key 环境 |
| `VITE_USE_MOCK_DATA=false`（默认） | 走 `server/ai/client.ts` → DeepSeek 真 AI |

**约束**：

- Mock **永不进入生产路径**
- Mock 与真实 API **共用同一套 shared types 与 validation**，不得出现两套 schema
- Mock 必须**读取全部输入**（product / selling_points / styles / count / target_users / scenarios / goal）并生成**与输入相关**的内容；**禁止"无论输入什么只替换产品名"**
- Mock 覆盖范围：generate / rewrite / score / title variants / compliance / reference analyze

---

## 10. Markdown 只是导出格式

产品核心是 AI 内容工作台。Markdown / TXT / JSON 仅是**导出格式**，不构成产品工作模式。

---

## 11. 小红书平台数据限制（重要）

**当前无法获得真实平台数据**（无账号授权、开放平台能力分阶段开放）。

因此：

- **禁止**伪造曝光、点赞、收藏、评论、分享、关注、转化
- 数据看板分两部分：
  - **A. 本地内容生产数据**（可真实统计）
  - **B. 发布后复盘**：允许用户**手动录入**上述指标后再计算
- 界面必须明确标注：**「数据由用户手动录入，暂未连接小红书平台」**
- 未接入时显示 **「尚未连接平台数据」**

**禁止**声称可实时读取笔记数据或自动发布。

## 附：V2 工程约束

- 保持 `server/ai/client.ts` 为**唯一 AI 出口**
- 保持 `app/shared` 为前后端**共同事实来源**
- **AI 负责**：语义理解、内容策略、创意、角度、文案、自检、质量判断
- **程序负责**：输入校验、数量、风格分配、ID、多样性计算、评分数值合法性、schema、排序、筛选、localStorage、状态、错误处理
- 不得删除现有稳定代码；确需重构时先保留行为再迁移
- 不得破坏 `vite.config.ts` 的 proxy / bypass（白屏修复）
